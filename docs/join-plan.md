# Join 與多階段 Recipe：實作計畫

狀態：**已定案，待實作**（2026-11-17 討論）。實作時遇到新的問題，先補在「待討論」，定案後再更新這份文件。
實作完成後，內容整理進 [DESIGN.md](../DESIGN.md)（§6 Recipe 格式、§7.2、§8、§9），這份文件就刪掉。

## 背景

目前一個 Recipe 只有一個輸入（`inputs` 限定一項）。M5 剩下的合併查詢（join）、附加查詢（append）需要好幾份資料，
而且每份資料常常要各自清理（例如門市對照表要先去掉空白列、改欄名），所以 Recipe 改成好幾個依序執行的階段。

M5 第一批（移除重複、取消樞紐、群組彙總、樞紐）已完成，不受這次修改影響。

## 已定案

1. **Recipe 由階段（stage）組成**：每個階段是「一個輸入 → 步驟 → 一個輸出」，**嚴格依序執行**；
   一個階段只能引用前面階段的輸出，所以不會有循環。
2. **輸出**：中間階段的輸出**一定是暫存的 parquet**，用階段名稱引用（例如 `@門市對照`），執行完就刪掉；
   最後一個階段的輸出**一定是實際檔**（位置在匯出時才選，和現在一樣，Recipe 不記）。
3. **輸入**：讀實際檔（現有的讀取方式，加上新的「parquet」讀取方式），或讀前面階段的引用。
   第一個階段只能讀實際檔；之後的階段兩種都可以。每個檔、每個引用都是來源檔。
4. **Join 是一般的步驟，右邊用引用指定**（前面階段的輸出，或一個實際的 parquet 檔），可以放在步驟清單的任何位置，
   也可以連續 join 好幾張表。左邊還沒合併時，**每個來源檔各自和整張右表 join**（join 是一列一列查表，結果和怎麼分檔無關）；
   右表不分來源檔，一律當成一整張表。
5. **讀引用時保留上游的 `__source_file`、`__line_no`**：警告可以一路指回原始檔的行號；
   上游還沒合併的話，這個階段照樣每個原始來源檔分別處理。
   讀外部的實際 parquet 檔則重新編號：`__source_file` 是檔名，`__line_no` 是第幾列（從 1 起）。
6. **右表的鍵重複就報錯**：列出重複的鍵，以及它們在右表的來源檔與行號；要先在右表那個階段「移除重複」或修正資料。
   絕不默默多出列。
7. **沒對到的列預設產生警告、可以關掉**：左連接（沒對到的列帶進來的欄是空值）、內連接（沒對到的列會被拿掉）時，
   附左邊的來源檔與行號。「只留沒對到的」「只留有對到的」本來就是在分對不對得到，不產生這種警告。
8. **Recipe 一律用 `stages`**：舊的寫法（最外層直接放 `inputs` / `steps` / `output`）不收，開啟時報錯並說明新寫法。
   Recipe 格式還沒發版，版本號維持 `1.0`。範例 Recipe、AI skill 一起改成新寫法。
9. **畫面：最左邊一排階段分頁**：點分頁切換階段，旁邊的步驟面板顯示這個階段的「讀取資料 → 步驟 → 輸出」
   （和現在的步驟面板一樣）。**每個階段都有名稱，新增階段時一定要命名**；第一個階段預設叫「預設階段」。
10. **引用名稱就是階段名稱**：階段叫「門市對照」，後面就用 `@門市對照` 引用它的輸出。階段名稱不能重複；
    改階段名稱時，程式一併改掉所有引用它的地方。
11. **新增的階段預設插在目前階段的前面**（新增的通常是給目前階段用的對照表）；命名的對話框裡可以改成「放在後面」。
    分頁可以拖曳調整順序。
12. **刪除或移動階段會弄壞引用時擋下來**：訊息列出是哪個階段的哪一步在引用它，要先改掉那些引用。
    Recipe 永遠不會處在引用壞掉的狀態。
13. **讀引用是一種讀取方式**：讀取方式多一個「前面階段的輸出」，選了就勾選要讀哪些階段（每個階段依保留的上游來源檔各自是來源檔）。
    一個輸入只有一種讀法，引用和實際檔不混在一起；要和實際檔一起附加，就先開一個階段讀那個檔（不加任何步驟也可以）。
14. **join 表單看右表：點一下跳到那個階段**：右表旁邊有「前往 @階段名稱」，點了切到那個階段的分頁、選到它的輸出；
    不另外做預覽元件。表單照樣由 schema 自動產生（選右表、鍵的對應用左右兩個欄位選單、勾選要帶的欄）。
15. **外部 parquet 自己帶的系統欄位改名成一般欄保留**：`__source_file` → 「原始來源檔」、`__line_no` → 「原始行號」、
    `__sheet` → 「原始工作表」（其他 `__` 開頭的欄同樣去掉 `__`、前面加「原始」），追溯資訊不會弄丟，不需要就用「刪除欄」拿掉。
    改名後和檔案裡的欄撞名時報錯。
16. **附加查詢時同名欄型別不一樣就報錯**：讀取時就檢查，指出哪一欄在哪個來源是什麼型別，要先在前面的階段轉成一樣。
    放寬兩種情況：整欄都是空值的不算衝突；小數位數不同時自動取位數多的。
17. **大檔時右表的預覽預設用樣本，join 設定畫面可以「完整跑一次」**：右表是樣本時，join 步驟與它的「沒對到」警告
    標示「右表是樣本，匯出時可能對得到」。按「完整跑一次」就把右表那個階段串流完整跑一次、寫成暫存檔（有進度），
    之後預覽用完整的右表；右表的階段（或它的上游）改了就回到樣本。
18. **新的「合併」分類**：放「合併查詢」（join），「合併來源檔」也從「列」移過來（附加查詢就是用它做的）。

## 實測（Polars 2.1）

- `join(..., maintain_order="left")`：左連接、內連接、`anti`、`semi` 串流執行和整份讀進記憶體的結果都一樣，
  左邊的順序與行號不變。**沒有 `maintain_order` 時串流的順序會亂**，一定要加。
- 左邊 3,000 萬列、右表 1,000 列：串流 join 0.5 秒，峰值記憶體 614 MB（不 join 時 426 MB）。
  右表整份放進記憶體（hash table），左邊串流，所以**右表要放得進記憶體**。
- 右表的鍵重複：Polars 不報錯，左邊對到的列會複製成好幾列（200 萬列變成 2,001,666 列）；
  `validate="m:1"` 會讓整個執行失敗，訊息也不好懂。所以鍵重複要自己先檢查（右表本來就整份放進記憶體，檢查很便宜）。

## Recipe 格式（草案）

```json
{
  "tablade_recipe": "1.0",
  "name": "門市銷售明細（補上門市名稱）",
  "stages": [
    {
      "name": "門市對照",
      "input": { "files": ["data/門市對照.csv"], "reader": "csv", "encoding": "auto" },
      "steps": [
        { "id": "a1", "type": "trim_clean", "columns": ["門市代號", "門市名稱"] }
      ]
    },
    {
      "name": "預設階段",
      "input": { "files": ["data/明細_*.csv"], "reader": "text_lines", "encoding": "auto" },
      "steps": [
        { "id": "s1", "type": "remove_top_rows", "n": 2 },
        { "id": "j1", "type": "join", "right": { "ref": "門市對照" },
          "on": [{ "left": "門市", "right": "門市代號" }], "how": "left", "columns": ["門市名稱"] }
      ],
      "output": { "format": "parquet", "keep_system_columns": true, "manifest": true }
    }
  ]
}
```

- 讀引用的輸入：`{ "reader": "stages", "stages": ["一月明細", "二月明細"] }`（每個階段依保留的上游來源檔各自是來源檔；欄位名稱實作時再定）。
- 每個階段都要有 `name`，整份 Recipe 不能重複；引用（`{ "ref": "階段名稱" }`）只能指到前面的階段。
  中間階段的輸出沒有被任何階段引用時，驗證器給警告。
- 步驟 `id` 整份 Recipe 不能重複（警告、處理紀錄都用步驟 id 指到哪一步）。
- 只有最後一個階段寫 `output`（實際檔的設定：`format`、`keep_system_columns`、`manifest`）；中間階段不寫，一定是暫存檔。

## Join 步驟（`join`「合併查詢」，分類「合併」）

**參數**

| 參數 | 說明 |
|---|---|
| `right` | 右表：`{ "ref": "門市對照" }`，或 `{ "file": "data/門市.parquet" }` |
| `on` | 鍵的對應，可以多組：`[{ "left": "門市", "right": "門市代號" }]` |
| `how` | `left` 左連接（預設）、`inner` 內連接、`anti` 只留沒對到的、`semi` 只留有對到的 |
| `columns` | 要從右表帶進來的欄。建立步驟時預設是右表全部的非鍵資料欄，可以刪減；`anti` / `semi` 不帶欄 |
| `warn_unmatched` | 沒對到的列產生警告（預設開；只有 `left` / `inner` 有效） |

**行為**

- `per_file = False`：一列一列查表，結果和來源檔怎麼分無關（registry 的測試會檢查）。
- `maintain_order="left"`；保留左邊的系統欄位，右表的系統欄位不帶進來。
- 鍵的型別兩邊要一樣（文字對文字、日期對日期）；不一樣時報錯並提示先轉型。鍵是空值時不算對到。
- 右表的鍵重複：報錯（見已定案 6）。
- 帶進來的欄和左邊的欄撞名：報錯，要先改名。
- **`apply()` 仍是純函式**：引擎在套用前把 `right` 解析成 LazyFrame 交給步驟（步驟自己不讀檔）。
  介面怎麼傳（例如 `apply(lf, refs)` 或套用前先綁定右表）實作時決定。
- 新的欄位效果 `join`：`left` / `inner` 時等於新增 `columns`，`anti` / `semi` 時欄位不變。
  驗證器依序推算每個階段的輸出欄位，所以右表是引用時可以檢查 `on[].right` 與 `columns` 是否存在；
  右表是實際 parquet 檔時，驗證器（只用標準函式庫，讀不了 parquet）不知道欄位，不檢查。
- 內連接的「沒對到」警告要在拿掉列之前算出來（警告目前是對步驟的輸出算的），做法實作時實驗。

## 附加查詢

不另外做步驟：輸入讀好幾個前面階段的輸出（或好幾個 parquet 檔），各當來源檔，再用「合併來源檔」接成一份，就是附加查詢。
欄位不一樣時缺的欄補空值（現在讀多個檔就是這樣對齊欄位）；同名欄型別不一樣時報錯（見已定案 16）。

## 讀 parquet

- 新的讀取方式 `parquet`：每個檔是一個來源檔，欄位與型別照檔案（不是全部文字）。
- `__source_file` 是檔名、`__line_no` 是第幾列；檔案自己帶的 `__` 開頭欄位改名成一般欄保留（見已定案 15）。
- 驗證器不知道 parquet 的欄位（同 CSV 沒提供標題時），試跑時才檢查。

## 執行、預覽、處理紀錄

- **執行**：依序跑每個階段。串流時中間階段寫成暫存 parquet（放在現有的暫存資料夾，沿用鎖檔與清理機制），
  下一個階段用 `scan_parquet` 讀；最後一個階段寫出實際檔。不管成功或失敗，執行完都刪掉暫存檔。
  小資料整份讀進記憶體時，中間結果直接留在記憶體，不必寫檔。
- **警告**：每個階段各自收集；階段的輸出就是一個邊界（和彙總、合併來源檔一樣，之前步驟的警告在這裡先算好），
  寫成引用時暫存欄位拿掉。
- **進度**：每個階段一段（例如「階段 1/2：門市對照」），各自顯示處理到第幾行。
- **預覽**：每個階段各自預覽與快取；被引用的階段先算好。大檔時每個階段用樣本；右表只有樣本時標示出來，
  join 設定畫面可以完整跑一次右表（見已定案 17）。
- **處理紀錄（manifest）**：記每個階段的輸入（實際檔的 SHA-256、引用名稱）、每一步、警告；
  中間暫存檔記列數與 SHA-256（檔案刪掉了，紀錄留著）。

## 實作順序

1. **Recipe 格式**：`recipe/schema.py`（`Stage`：名稱、輸入（實際檔或前面階段的輸出）、步驟；只有最後一個階段有 `output`）、
   `recipe/validator.py`（`stages`、階段名稱不重複、引用只能指到前面、每個階段的欄位推算、步驟 id 全域不重複、`join` 欄位效果、舊寫法的報錯訊息）、
   schema lock、`skill.py` 的說明、三個範例 Recipe 改寫、`engine/check.py`。
2. **讀取**：`parquet` 讀取方式（原本的系統欄位改名保留）；讀前面階段的輸出（保留上游的來源檔與行號）；附加時的型別檢查。
3. **引擎**（`engine/run.py`）：依序執行階段、暫存檔、警告、進度、處理紀錄。
4. **Join 步驟**（`steps/join.py`）：參數、`apply()`、鍵重複與沒對到的檢查、建立步驟時的建議值。
5. **Session、API、前端**（`session.py` 有 pytest，`api.py` 只包一層，`bridge.ts` 加型別）：
   最左邊的階段分頁（新增時命名、插在目前階段前面、拖曳排序、擋下會弄壞引用的刪除與移動、改名時一併改引用）、
   每個階段的預覽與快取、讀取方式「前面階段的輸出」、join 表單（前往右表、完整跑一次右表、樣本標示）、
   新的「合併」分類（「合併來源檔」移過來）。
6. **範例與假資料**：`fixtures.py` 加門市對照表；新增 join 與附加查詢的範例 Recipe。
7. **測試**：串流＝整份讀進記憶體（join 在合併來源檔之前與之後、引用保留行號、鍵重複報錯、沒對到警告、附加查詢）、
   驗證器、範例 Recipe、自我檢測。
8. **文件**：DESIGN.md、兩份 README、CLAUDE.md（規則有變時），刪掉這份計畫。
