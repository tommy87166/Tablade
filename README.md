**Tablade** (*Table + Blade*) is a desktop data cleaning tool in the spirit of Power Query's
*Applied Steps*: you build a **linear list of steps** — remove junk rows, split columns, fill
down, parse numbers and dates — preview the result after every step, and export clean
**Parquet** or **CSV** (chosen per stage; CSV is UTF-8 with a BOM so Excel opens it directly), into an `output` folder next to the recipe. Every row carries the file and line it came from, and a manifest in the `log` folder records
the recipe, the SHA-256 of every input and of the output, and each step's row count and warnings. The steps are
saved as a **recipe JSON**, so the same cleanup can be re-run on next month's files.
**Every file stays on your machine**: there is no server and no upload. The only network call is a
version check against GitHub at start-up (nothing is sent, nothing is downloaded).

> [!IMPORTANT]
> **This repository does not, and must not, contain any real data.**
> Test data is always generated by `scripts/gen_fixtures.py`; a pre-commit hook blocks data
> files and anything that looks like personal data. See [Keeping real data out](#️-keeping-real-data-out-of-the-repo).

> **Status: M5 — multi-stage recipes, join and append done.** Build a recipe in the window (applied steps, live preview, forms
> generated from the step schemas), let Microsoft 365 Copilot write one with the generated skill, or run it
> from the command line. A recipe is a list of stages run in order (each stage reads files or the results of
> earlier stages), so differently formatted data can be cleaned separately, then appended or looked up with a join.
> 25 step types: besides removing junk rows, splitting (by delimiter or fixed position),
> copying a column on matching rows (e.g. a section title) and filling down, filtering and combining source files, you can classify rows and extract with regular expressions to
> flatten sectioned print-format reports, read Excel sheets, clean text (full-width to half-width, invisible characters), replace values,
> convert text to numbers and dates (rows that fail are reported with their line numbers), and remove, keep /
> reorder or rename columns, remove duplicates, unpivot, group by and pivot (each source file on its own until you
> combine them), and join another stage's result. The bottom pane's Types tab shows each column's type, and every export comes with a
> manifest. See the [roadmap](#️-roadmap).

## 💡 Why Tablade

Real-world data rarely arrives clean. It comes **split across dozens of files**, as
**printed-style TXT reports** with title noise, blank lines and subtotals, or as **Big5/cp950**
exports that most tools refuse to read. The usual fix — merge by hand, then filter in a
database browser — is slow and impossible to reproduce.

Five needs drove this tool:

- **Messy input, step by step.** Read each physical line as-is (keeping its original line
  number), then clean it with small, previewable steps instead of one giant script.
- **Reproducible.** Steps are data, not code. Save them as a recipe, re-apply it to new
  files, and get the same result — with a warning instead of a silent change when the new
  data has more columns or segments than expected.
- **Data never leaves the machine.** Everything runs locally, and **outbound connections are
  ruled out at the code level** (see [🔒 Security — no egress](#-security--no-egress)).
- **Runs on locked-down computers.** No Python install, no admin rights: Tablade ships as a
  single executable (or an unzip-and-run folder) for Windows and macOS.
- **Let an AI assistant write the recipe.** Tablade generates an Agent Skills package
  (`SKILL.md`, step catalog, schema and a validator) from its step registry, so an assistant such
  as Microsoft 365 Copilot can turn a plain-language description into a recipe and check it.
  The skill shares its version number with the recipe format (see [`DESIGN.md` §17](DESIGN.md)).

## 🔧 How it works

| Layer | Technology | Role |
|---|---|---|
| Engine | [Polars](https://pola.rs/) 2.x (Python API) | Each step compiles to a LazyFrame operation; the preview reads inputs of up to 200,000 lines in full and beyond that samples the beginning and end of each file (at most the first 100,000 + last 1,000 lines, all files together within a budget set by this computer's memory); export streams to Parquet or CSV. |
| Window | [pywebview](https://pywebview.flowrl.com/) 6 | Native window (WebView2 on Windows, WKWebView on macOS). JS calls Python directly — **no HTTP server, no open port**. |
| Front end | React 19 + TypeScript + Vite, [shadcn/ui](https://ui.shadcn.com/) (Radix + Tailwind CSS v4) | Built into **one self-contained HTML file** (~700 KB, ~200 KB gzipped) that Python loads as a string. |
| Encoding | Python codecs | Auto-detects `utf-8-sig` → `cp950`; reports the first undecodable byte and line, or (line-by-line readers only) replaces undecodable characters with `�` and warns. |
| Excel | [fastexcel](https://github.com/ToucanToco/fastexcel) (calamine) | Fast, read-only XLSX / XLS. |
| Recipe | pydantic v2 | Validates recipe JSON. |
| Packaging | PyInstaller 6 + uv | `onefile` and `onedir` builds from one lock file. |

### Readers

| Mode | Use for | Output columns | Status |
|---|---|---|---|
| `csv` | Clean CSV | all columns as text | ✅ M0 (system columns in M1) |
| `text_lines` | Messy CSV / TXT reports — every physical line kept verbatim | `__source_file`, `__line_no`, `line` | M1 |
| `excel` | XLSX / XLSM / XLS / ODS, one sheet or `*` for every sheet of every file — every row is data (no header row), every cell read as text | `__source_file`, `__line_no` (the Excel row number), `A`, `B`, `C`…; with `*` also `__sheet` (each sheet is processed as its own source) | ✅ M4 |
| `parquet` | Parquet files — columns and types as stored; the file's own `__` columns are kept as ordinary columns renamed to 原始… | `__source_file` (file name), `__line_no` (row number), all columns | ✅ M5 |
| `stages` | The results of earlier stages — each source stays its own source (named `@stage／file`); append them with *Combine source files* | `__stage`, the upstream system columns (warnings still point at the original lines), all columns | ✅ M5 |

- Columns starting with `__` are system columns: hidden in the UI by default, optional on export.
- A recipe keeps a **file list**: files inside the recipe's folder are stored as relative paths,
  others as absolute paths, and you can type a path with `*`, `?` or `[…]` by hand (a path that is an
  existing file is used as-is, so names containing `[` or `?` still work). Data is read only when you
  press “Load & preview” in the toolbar, and only once every entry in the list is found. To just
  export, press “Process & export” directly: no loading needed — it first test-runs every stage on
  the first 2,000 lines of each file and stops at the failing step.
- Multiple files each get their own pipeline and are joined in list order at a “Combine source files”
  step or before writing — mismatched columns become null.
- Output file names (each stage's `output_file`) are names only; the extension follows the format. They
  can't contain path characters, start with “.” or be a Windows reserved name (`CON`, `NUL`, `COM1`…),
  the name can be at most 200 bytes, names must be unique within a recipe (case-insensitive, compared
  after NFC normalization; `明細.csv` and `明細.parquet` count as the same), and no output may overwrite an input file.
- Each file's row order is fixed at read time (`__line_no`) and every step keeps it, so steps never
  sort; per-file steps (fill down, remove top/bottom rows) work file by file without window
  functions, which keeps memory flat on multi-GB inputs.

### Data flow

```
pywebview window — frontend/ (React + shadcn/ui, one HTML file)
      │  window.pywebview.api.xxx()  (Promise, in-process — no HTTP)
      ▼
api.py  (argument conversion + error wrapping only)
      ▼
recipe/ (pydantic) ──► engine/run.py        steps (data) → Polars LazyFrame
      ┌──────────────────────┼──────────────────────┐
      ▼                      ▼                      ▼
ingest/                steps/                  export/
encoding, line reader, pure functions:         Parquet / CSV + manifest
CSV / Excel, line no.  LazyFrame → LazyFrame

cli.py — `tablade run recipe.json` runs the same engine without the UI
```

### 🔒 Security — no egress

- **One network call, for the version only.** At start-up `src/tablade/update.py` sends one GET
  to the GitHub API to read the latest release's version number. If there is a newer version,
  the start page shows the download link. Nothing about you or your data is sent, nothing is
  downloaded, and nothing updates itself. Set `TABLADE_NO_UPDATE_CHECK=1` to turn it off.
- **No other network code.** `scripts/check_code_policy.py` parses every file in `src/` and rejects
  imports of `socket`, `http`, `urllib`, `requests`, `httpx`, `aiohttp`, `ssl` and friends (only
  `update.py` may use `urllib.request`), plus `eval` / `exec` / `compile` / `__import__` /
  `importlib.import_module`. Only `desktop.py` may start other programs (`subprocess`, `os.system`…;
  it opens a local folder with the system's file browser), and Polars `read_*` / `scan_*` calls may not
  read URLs or cloud storage (`storage_options`). It runs in pre-commit and CI.
- **No local server.** The page is loaded as an HTML string, so pywebview never starts its
  built-in HTTP server and no port is opened.
- **Content-Security-Policy `default-src 'none'`** (injected at build time). The page cannot fetch, connect, frame or
  load any external resource. `'unsafe-eval'` is allowed only because pywebview's JS bridge
  needs it.
- **Data is never rendered as HTML.** Cell values are written with `textContent`, so a cell
  containing markup can't turn into script that calls Python.
- **Residual risk (known):** the policy check covers Tablade's own code, not third-party
  packages, and it is a gatekeeper rather than a sandbox: deliberate tricks (such as building a name
  as a string and calling `getattr`) get past it. Dependencies are pinned in `uv.lock` and kept to a
  small, well-known set.

### 🛡️ Keeping real data out of the repo

- `.gitignore` excludes every data format (CSV, TXT, Excel, Parquet, databases, PDF, archives…).
- The pre-commit hook `scripts/check_no_data.py` blocks data-file extensions, files over 1 MiB,
  strings that pass the Taiwan national ID checksum, 8-digit business IDs next to their keyword,
  and any term listed in a private, git-ignored `.tablade-denylist`. Matches are masked in the
  output so they don't leak again through CI logs.
- Real recipes can contain sensitive filter values too, so only `examples/` recipes built on
  generated data may be committed.

### 📦 Packaging & distribution

| Platform | File | Notes |
|---|---|---|
| Windows | `tablade-windows-x64-onefile.zip` | One `tablade.exe` |
| macOS | `tablade-macos-arm64-app.zip` | `Tablade.app` (an onedir build wrapped as an app; PyInstaller has no onefile `.app`); first launch: right-click → **Open** |
| AI skill | `tablade-recipe-skill-v<recipe version>.zip` | For Microsoft 365 Copilot and other AI assistants |

- `scripts/build.py` builds what is released on the current platform (Windows: onefile; macOS:
  `Tablade.app`), runs the built-in self-test, and zips it. `scripts/build.py onedir` still builds a
  Windows onedir folder by hand — the fallback when onefile is blocked.
- CI (`.github/workflows/build.yml`) runs the same script on Windows and macOS. When a `v*` tag is
  pushed it first checks that the tag matches `__version__` in `src/tablade/__init__.py`
  (`scripts/check_release.py`) and stops the release if it doesn't, then attaches the zips and the AI
  skill to a Release.
- To release: set `__version__` (e.g. `0.2.0`), commit and push, then `git tag v0.2.0 && git push origin v0.2.0`.
- Binaries are **unsigned**. On macOS you can also run `xattr -dr com.apple.quarantine Tablade.app`.
- The Windows build is a windowed app, so command-line output is not shown; use
  `tablade.exe selftest --out result.json` and read the JSON.

## 🤖 Writing recipes with Microsoft 365 Copilot

Tablade generates an [Agent Skills](https://learn.microsoft.com/en-us/microsoft-365/copilot/extensibility/agent-builder-add-skills)
package from its step registry: `SKILL.md`, a step catalog with examples, the recipe JSON Schema, and a
single-file validator that only needs the Python standard library (Copilot's sandbox can't install packages).
The skill's version is the recipe format version, so a skill always writes recipes this Tablade can open.

1. **Get the skill.** In Tablade: **Copilot → Download Copilot skill**, or `tablade skill`.
2. **Add it to an agent.** In Agent Builder: *Configure → Skills → Add*, upload the whole zip.
   (To check what the sandbox can do first, upload the probe from `tablade skill --probe` and say “執行 Tablade probe”.)
3. **Ask Copilot.** Upload the data (or a summary from `tablade profile 資料.csv`) and describe the cleanup.
   Copilot writes the recipe and checks it with `scripts/validate_recipe.py`.
4. **Open it in Tablade.** Put the recipe next to the data and use **Open Recipe**. Tablade validates it and
   dry-runs every step on the real data; if anything is wrong, **Copilot → Check and copy error report** gives
   you a report to paste back to Copilot.

## 🛠️ Development

Requires [uv](https://docs.astral.sh/uv/) and Node.js 24+. To read Deflate64-compressed files in zips, or to build a release, you also need [Rust](https://rustup.rs/) (`uv sync --group native` builds the module in `native/`; see [native/README.md](native/README.md); the crates it uses are MIT-licensed, with the license texts in `native/LICENSES/`, also shipped in the app); it's optional for working on anything else.

```bash
uv sync                                              # create the venv from uv.lock
uv sync --group native                               # also build the Rust module (Deflate64 in zips; needs Rust)
npm --prefix frontend ci                             # install front-end dependencies
npm --prefix frontend run build                      # build frontend/dist/index.html (needed before running the app)
uv run pre-commit install                            # install the data-protection hook (required)
uv run pytest                                        # run the tests
uv run tablade                                       # open the window from source
uv run python scripts/gen_frontend_dev_data.py       # fake API data for the browser mock (not committed)
npm --prefix frontend run dev                        # Vite dev server (mock API in a normal browser)
TABLADE_DEV_URL=http://localhost:5173 uv run tablade # the real window, with hot reload
uv run python scripts/gen_fixtures.py tmp/fixtures   # generate fake sample data
uv run python scripts/build.py --gui-smoke           # build the release (Windows: onefile, macOS: .app), self-test, zip to dist/release/
uv run --group icons python scripts/make_icons.py    # regenerate icon.ico / icon.icns from assets/icon.svg
```

Command line:

```bash
tablade                              # open the window
tablade selftest [--out result.json] # self-test with generated data (exit code 0 = pass)
tablade gui --smoke                  # open the window, self-test, close
tablade convert in.csv out.parquet [--encoding auto|utf-8|utf-8-sig|cp950|big5hkscs]
tablade run recipe.json [--out-dir DIR] [--json]  # run a recipe: outputs go to output/, manifests to log/ (default: the recipe's folder); print row counts per step
tablade validate recipe.json [--run] [--json]    # check a recipe (--run: dry-run on the real data)
tablade schema [--out spec.json]                 # step catalog + recipe JSON Schema
tablade skill [--out x.zip] [--probe]            # AI skill for Microsoft 365 Copilot (or the sandbox probe)
tablade profile 資料.csv [--lines 30] [--mask] [--out summary.md]  # compact summary of a data file for an AI assistant (--mask: mask the content and file names)
tablade version
```

Try the example:

```bash
uv run python scripts/gen_fixtures.py examples/data
uv run tablade run examples/sales_detail.recipe.json
uv run tablade run examples/sales_report.recipe.json   # sectioned print-format report → one row per detail line
uv run tablade run examples/sales_excel.recipe.json    # Excel sheet: drop the title rows, convert dates and numbers
uv run tablade run examples/sales_combined.recipe.json # 4 stages: append a text export and an Excel sheet, then join an item table
```

If there are words that must never appear in the repo (people's names, company names, project code names…),
list them in `.tablade-denylist` at the repo root (one per line; it is already in `.gitignore`), and pre-commit
blocks any file that contains them.

## 🗂️ Code architecture

```
src/tablade/
├─ app.py             pywebview entry point; loads frontend/dist/index.html as a string
├─ api.py             JS bridge: argument conversion and error wrapping only
├─ session.py         the recipe being edited: state, per-step cache, undo / redo (UI talks only to this)
├─ skill.py           generates the AI skill (SKILL.md, step catalog, schema, validator) from the registry
├─ profile.py         data-file summary for AI assistants
├─ cli.py             command line (gui / run / validate / schema / skill / profile / selftest / convert / version)
├─ selftest.py        packaged-environment self-test on generated data
├─ fixtures.py        deterministic fake data (tests, self-test, examples)
├─ i18n.py            UI language (Chinese / English)
├─ update.py          version check at start-up (the only network call)
├─ usage.py           memory and temp-folder usage; desktop.py opens a local folder
├─ recipe/            pydantic models, version, stdlib-only validator, spec + schema lock
├─ steps/             one module per step family, registered in registry.py
├─ engine/            run a recipe (row counts, warnings with line numbers, Parquet / CSV output), check = validate + dry-run
├─ ingest/            encoding detection, text_lines / csv / Excel / Parquet readers, glob, transcoding, column alignment
└─ export/            output locations and file-name checks, manifests
frontend/             Vite + React + TypeScript + shadcn/ui; bridge.ts mirrors api.py
assets/               icon.svg (source), icon.ico, icon.icns, icon.png
scripts/              build, make_icons, gen_fixtures, gen_frontend_dev_data, check_no_data, check_code_policy,
                      check_i18n, check_release, update_schema_lock
tests/                pytest suite
tablade.spec          PyInstaller config (onefile / onedir via TABLADE_BUILD)
```

- **Steps are data, not code.** A recipe stores step type + parameters; the engine (`engine/run.py`)
  maps them to Polars operations. User input is never executed.
- **Every step is a pure function** `apply(lf) -> LazyFrame` (the parameters are the step model's
  fields) — no file I/O, no UI.
- **Structure-defining steps** (promote headers, split into N columns, pivot) scan the data once
  when the step is created and freeze the column names into the recipe.
- Full design and rationale: [`DESIGN.md`](DESIGN.md).

## ⚠️ Known limitations

- **The Copilot skill hasn't been tried in Agent Builder yet**: whether its scripts can read files uploaded in the chat, and the sandbox's Python version, still need the probe.
- **A join's right table is held in memory** (the left side streams). Duplicate keys in the right table are an
  error rather than silently multiplying rows. With large inputs the preview's right table is a sample; the join
  form can run that stage once on all the data.
- **Large files are previewed from a sample.** Above 200,000 lines the preview uses the beginning
  and end of each file (at most the first 100,000 and last 1,000 lines; with many files, all of them
  together stay within a budget of 32 MB per thread, at most 256 MB, less when memory is short; set
  `TABLADE_SAMPLE_MB` to fix the size), so per-step row counts in the UI are sample counts;
  the data pane says “Sample mode”, plus a red “Warning: preview may be inaccurate” when a step that
  needs the whole file (remove duplicates, group by, pivot) comes before the selected step (hover to see
  which steps). Export streams through everything, the progress window shows how many
  lines have been processed, and afterwards “Output” reads the exported file and says “Full mode”.
  Streaming export reports only the final row count, and its warnings cover the rows that are still
  in the output. Group-by and pivot previews are computed from the sample too (pivot reads its new
  columns from the preview data; values that only show up at export time are reported as warnings).
- **Non-UTF-8 files are transcoded to a temporary copy first** (about 230 MB/s per core for cp950;
  files of 64 MB or more are split and transcoded by up to 8 processes at once, with the same result as a
  single core). With `text_lines` the copy is compressed Parquet and needs only about 1/10 of the file
  size in temp space; with `csv` it is a full UTF-8 copy and needs roughly 1.5× (prefer `text_lines` for
  large files). The copy is deleted when the window closes, and copies left by a crash are removed the
  next time Tablade starts.
- **`csv` reader line numbers assume no multi-line fields**; use `text_lines` for such files.
- **Undecodable characters** (such as Big5 custom characters, which Python's cp950 can't read) stop the
  file by default. With `text_lines` and `zip_lines` you can set “Undecodable characters” to “Replace with �”:
  each 2-byte character becomes two `�` (so fixed-width columns don't shift), the file is read anyway, and a
  warning plus the processing log say how many were replaced and on which lines. Different custom characters
  all become `��` and can't be told apart or restored. Not available for `csv`; read such files line by line
  and split by delimiter instead.
- **Zip support is for text files only (`zip_lines`, line by line)**: no need to extract first; `members`
  names the files inside the zip (for example `2026*/HEADER*.TXT`). Extract CSV and Excel files first;
  password-protected zips, zips inside zips, 7z and rar aren't supported. Deflate64 (which Windows Explorer
  may use for large files) is handled by the bundled Rust module.
- **onefile starts slowly** because it unpacks itself on every launch, and some antivirus or
  AppLocker setups block programs running from the temp folder. Only onefile is released for Windows;
  build an onedir folder with `uv run python scripts/build.py onedir` if that happens.
- **Unsigned binaries:** expect Gatekeeper (macOS) and SmartScreen (Windows) prompts.
- **macOS builds are Apple Silicon (arm64) only.**
- Join / group-by in Polars 2.x can't spill to disk yet; if memory becomes a problem, those steps
  may be handed to DuckDB later.
