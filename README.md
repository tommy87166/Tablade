**Tablade** (*Table + Blade*) is a desktop data cleaning tool in the spirit of Power Query's
*Applied Steps*: you build a **linear list of steps** — remove junk rows, split columns, fill
down, parse numbers and dates — preview the result after every step, and export clean
**Parquet** with a manifest that records exactly where every row came from. The steps are
saved as a **recipe JSON**, so the same cleanup can be re-run on next month's files.
**Every file stays on your machine**: there is no server, no upload, and no network code.

> [!IMPORTANT]
> **This repository does not, and must not, contain any real data.**
> Test data is always generated by `scripts/gen_fixtures.py`; a pre-commit hook blocks data
> files and anything that looks like personal data. See [Keeping real data out](#️-keeping-real-data-out-of-the-repo).

> **Status: M1 — engine.** Recipes, 8 step types, the validator and the command line work today
> (`tablade run` / `validate` / `schema`); the step-by-step UI arrives in M2. See the [roadmap](#️-roadmap).

## 💡 Why Tablade

Real-world data rarely arrives clean. It comes **split across dozens of files**, as
**printed-style TXT reports** with title noise, blank lines and subtotals, or as **Big5/cp950**
exports that most tools refuse to read. The usual fix — merge by hand, then filter in a
database browser — is slow and impossible to reproduce.

Five needs drove this tool:

- **Messy input, step by step.** Read each physical line as-is (keeping its original line
  number), then clean it with small, previewable steps instead of one giant script.
- **Reproducible.** Steps are data, not code. Save them as a recipe, re-apply it to new
  files, and get the same result — with a warning instead of a silent change when the new
  data has more columns or segments than expected.
- **Data never leaves the machine.** Everything runs locally, and **outbound connections are
  ruled out at the code level** (see [🔒 Security — no egress](#-security--no-egress)).
- **Runs on locked-down computers.** No Python install, no admin rights: Tablade ships as a
  single executable (or an unzip-and-run folder) for Windows and macOS.
- **Let an AI assistant write the recipe.** Tablade generates an Agent Skills package
  (`SKILL.md`, step catalog, schema and a validator) from its step registry, so an assistant such
  as Microsoft 365 Copilot can turn a plain-language description into a recipe and check it.
  The skill shares its version number with the recipe format (see [`DESIGN.md` §17](DESIGN.md)).

## 🔧 How it works

| Layer | Technology | Role |
|---|---|---|
| Engine | [Polars](https://pola.rs/) 2.x (Python API) | Each step compiles to a LazyFrame operation; preview runs `head(1000)`, export streams to Parquet. |
| Window | [pywebview](https://pywebview.flowrl.com/) 6 | Native window (WebView2 on Windows, WKWebView on macOS). JS calls Python directly — **no HTTP server, no open port**. |
| Front end | React 19 + TypeScript + Vite, [shadcn/ui](https://ui.shadcn.com/) (Radix + Tailwind CSS v4) | Built into **one self-contained HTML file** (~300 KB) that Python loads as a string. |
| Encoding | Python codecs | Auto-detects `utf-8-sig` → `cp950`; reports the first undecodable byte and line. |
| Excel | [fastexcel](https://github.com/ToucanToco/fastexcel) (calamine) | Fast, read-only XLSX / XLS. |
| Recipe | pydantic v2 | Validates recipe JSON. |
| Packaging | PyInstaller 6 + uv | `onefile` and `onedir` builds from one lock file. |

### Readers

| Mode | Use for | Output columns | Status |
|---|---|---|---|
| `csv` | Clean CSV | all columns as text | ✅ M0 (system columns in M1) |
| `text_lines` | Messy CSV / TXT reports — every physical line kept verbatim | `__source_file`, `__line_no`, `line` | M1 |
| `excel` | XLSX / XLS, one sheet | `__source_file`, `__sheet`, `__line_no`, columns | M4 |

- Columns starting with `__` are system columns: hidden in the UI by default, optional on export.
- Multiple files (glob) are combined with `diagonal_relaxed` concat — mismatched columns become null.
- Anything that depends on row order (fill down, remove top/bottom rows) sorts by
  `__source_file, __line_no` first, never relying on execution order.

### Data flow

```
pywebview window — frontend/ (React + shadcn/ui, one HTML file)
      │  window.pywebview.api.xxx()  (Promise, in-process — no HTTP)
      ▼
api.py  (argument conversion + error wrapping only)
      ▼
recipe/ (pydantic) ──► engine/compiler.py   steps (data) → Polars LazyFrame
      ┌──────────────────────┼──────────────────────┐
      ▼                      ▼                      ▼
ingest/                steps/                  export/
encoding, line reader, pure functions:         Parquet + manifest
CSV / Excel, line no.  LazyFrame → LazyFrame

cli.py — `tablade run recipe.json` runs the same engine without the UI
```

### 🔒 Security — no egress

- **No network code.** `scripts/check_code_policy.py` parses every file in `src/` and rejects
  imports of `socket`, `http`, `urllib`, `requests`, `httpx`, `aiohttp`, `ssl` and friends,
  plus `eval` / `exec` / `compile` / `__import__`. It runs in pre-commit and CI.
- **No local server.** The page is loaded as an HTML string, so pywebview never starts its
  built-in HTTP server and no port is opened.
- **Content-Security-Policy `default-src 'none'`** (injected at build time). The page cannot fetch, connect, frame or
  load any external resource. `'unsafe-eval'` is allowed only because pywebview's JS bridge
  needs it.
- **Data is never rendered as HTML.** Cell values are written with `textContent`, so a cell
  containing markup can't turn into script that calls Python.
- **Residual risk (known):** the policy check covers Tablade's own code, not third-party
  packages. Dependencies are pinned in `uv.lock` and kept to a small, well-known set.

### 🛡️ Keeping real data out of the repo

- `.gitignore` excludes every data format (CSV, TXT, Excel, Parquet, databases, PDF, archives…).
- The pre-commit hook `scripts/check_no_data.py` blocks data-file extensions, files over 1 MiB,
  strings that pass the Taiwan national ID checksum, 8-digit business IDs next to their keyword,
  and any term listed in a private, git-ignored `.tablade-denylist`. Matches are masked in the
  output so they don't leak again through CI logs.
- Real recipes can contain sensitive filter values too, so only `examples/` recipes built on
  generated data may be committed.

### 📦 Packaging & distribution

| Platform | File | Notes |
|---|---|---|
| Windows | `tablade-windows-x64-onefile.zip` | One `tablade.exe` |
| Windows | `tablade-windows-x64-onedir.zip` | Unzip and run `tablade\tablade.exe` — fallback when onefile is blocked or slow |
| macOS | `tablade-macos-arm64-app.zip` | `Tablade.app`; first launch: right-click → **Open** |
| macOS | `tablade-macos-arm64-onefile.zip` | Command-line single binary |

- `scripts/build.py` builds both variants, runs the built-in self-test on each, and zips them;
  CI (`.github/workflows/build.yml`) runs the same script on Windows and macOS and attaches the
  zips to a Release when a `v*` tag is pushed.
- Binaries are **unsigned**. On macOS you can also run `xattr -dr com.apple.quarantine Tablade.app`.
- The Windows build is a windowed app, so command-line output is not shown; use
  `tablade.exe selftest --out result.json` and read the JSON.

## 🛠️ Development

Requires [uv](https://docs.astral.sh/uv/) and Node.js 24+.

```bash
uv sync                                              # create the venv from uv.lock
npm --prefix frontend ci                             # install front-end dependencies
npm --prefix frontend run build                      # build frontend/dist/index.html (needed before running the app)
uv run pre-commit install                            # install the data-protection hook (required)
uv run pytest                                        # run the tests
uv run tablade                                       # open the window from source
npm --prefix frontend run dev                        # Vite dev server (mock API in a normal browser)
TABLADE_DEV_URL=http://localhost:5173 uv run tablade # the real window, with hot reload
uv run python scripts/gen_fixtures.py tmp/fixtures   # generate fake sample data
uv run python scripts/build.py --gui-smoke           # build onefile + onedir, self-test, zip to dist/release/
uv run --group icons python scripts/make_icons.py    # regenerate icon.ico / icon.icns from assets/icon.svg
```

Command line:

```bash
tablade                              # open the window
tablade selftest [--out result.json] # self-test with generated data (exit code 0 = pass)
tablade gui --smoke                  # open the window, self-test, close
tablade convert in.csv out.parquet [--encoding auto|utf-8|cp950|big5hkscs]
tablade run recipe.json [--json]                 # run a recipe, write Parquet, print row counts per step
tablade validate recipe.json [--run] [--json]    # check a recipe (--run: dry-run on the real data)
tablade schema [--out spec.json]                 # step catalog + recipe JSON Schema
tablade version
```

Try the example:

```bash
uv run python scripts/gen_fixtures.py examples/data
uv run tablade run examples/sales_detail.recipe.json
```

## 🗂️ Code architecture

```
src/tablade/
├─ app.py             pywebview entry point; loads frontend/dist/index.html as a string
├─ api.py             JS bridge: argument conversion and error wrapping only
├─ cli.py             command line (gui / run / validate / schema / selftest / convert / version)
├─ selftest.py        packaged-environment self-test on generated data
├─ fixtures.py        deterministic fake data (tests, self-test, examples)
├─ recipe/            pydantic models, version, stdlib-only validator, spec + schema lock
├─ steps/             one module per step family, registered in registry.py
├─ engine/            run a recipe (row counts, warnings with line numbers), check = validate + dry-run
├─ ingest/            encoding detection, text_lines / csv readers, glob + multi-file concat
└─ export/            atomic Parquet writer
frontend/             Vite + React + TypeScript + shadcn/ui; bridge.ts mirrors api.py
assets/               icon.svg (source), icon.ico, icon.icns, icon.png
scripts/              build, make_icons, gen_fixtures, check_no_data, check_code_policy
tests/                pytest suite
tablade.spec          PyInstaller config (onefile / onedir via TABLADE_BUILD)
```

- **Steps are data, not code.** A recipe stores step type + parameters; the compiler maps them
  to Polars operations. User input is never executed.
- **Every step is a pure function** `apply(lf, params) -> LazyFrame` — no file I/O, no UI.
- **Structure-defining steps** (promote headers, split into N columns, pivot) scan the data once
  when the step is created and freeze the column names into the recipe.
- Full design and rationale: [`DESIGN.md`](DESIGN.md).

## ⚠️ Known limitations

- **No step UI yet** (M2): recipes are written by hand, by an AI assistant, or with the CLI.
- **One input per recipe** for now; joining or appending several inputs comes with M5.
- **Files are read into memory and each step is collected** in M1 (cheap row counts and warnings).
  Fine for typical files on a 16 GB laptop; lazy execution with streaming export comes later
  without changing the steps.
- **`csv` reader line numbers assume no multi-line fields**; use `text_lines` for such files.
- **onefile starts slowly** because it unpacks itself on every launch, and some antivirus or
  AppLocker setups block programs running from the temp folder — use the onedir build then.
- **Unsigned binaries:** expect Gatekeeper (macOS) and SmartScreen (Windows) prompts.
- **macOS builds are Apple Silicon (arm64) only.**
- Join / group-by in Polars 2.x can't spill to disk yet; if memory becomes a problem, those steps
  may be handed to DuckDB later.
